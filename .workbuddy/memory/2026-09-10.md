# 2026-09-10

## 项目全景分析：dsagent-electron（产品名 WebAgent v6.0.0）

应要求对项目做了一次全量架构梳理，核心结论（供后续会话复用）：

- **架构已迁移**：从 Electron 5.x 迁移为 **Node Runtime + React PWA + Playwright 无头 Edge**。
  package.json 的 name 是 `webagent`，version 6.0.0，main 入口 `src/node/daemon.js`（不再是 Electron 主进程）。
- **五层结构**：
  1. 客户端：`src/renderer`（Vite + React 18 PWA，`dist-renderer` 为产物）+ `bin/dsagent-runtime-cli.js`（CLI），两者地位相同。
  2. 接入：`src/runtime/webapp-service.js`（静态托管 + 一次性票据换 HttpOnly Cookie + CSRF，默认动态端口）与 `src/runtime/api-server.js`（REST + SSE + OpenAI 兼容，默认 5858）。
  3. 编排：`run-service.js`（Run 生命周期 / tool-loop ≤20 轮 / 子代理深度 3 / agent_cluster）、`context-manager.js`（按 provider 窗口估算并压缩）、`tool-registry.js` + `tool-executor.js`、`session-store.js` / `config-store.js`。
  4. 调度：`provider-manager.js` 按模型名路由（`deepseek.` / `qwen.` / `chatgpt.` → 网页 Worker；`qwen.gateway` → Rogator 侧车；其余 → API），`worker-pool.js` 租约式并发（deepseek 2 / qwen 8 / chatgpt 2）。
  5. 执行：`src/node/provider-worker-factory.js` 用 Playwright 驱动系统 Edge 访问真实网页；`deepseek-harness-service.js` 与 `rogator-service.js` 为两个官方侧车。
- **三种会话模式**由 `src/runtime/mode-policy.js` 强制：chat 关闭全部工具/技能/子代理/记忆写入；project 绑定 workspace 全开；work 默认 `D:\Work\WAWorkSpace` 并强制写记忆。
- **重要纠偏（勿再误判）**：根目录的 `tools/tool-*.js`、`agent-engine.js`、`inject-deepseek.js`、`inject-qwen.js` **不是死代码**。
  `provider-worker-factory.js` 的 `buildInject()` 会把 tools/ 下全部 tool-*.js + agent-engine.js + inject-*.js 拼接成一段脚本，
  通过 `webContents.executeJavaScript` 注入到无头 Edge 页面，由页面内 DOM 协议驱动 Provider 网页。它们运行在浏览器侧，不在 Node 侧。
- **真正的遗留**：根目录 `server.js`（在 daemon.js 中以 `legacyAgentServices` 注入，仅作 MCP 与兜底兼容），是最大的单体待剥离项；
  `tools/tool-*.js` 仍用旧的 `<tool:read>` XML 协议，与新的 `tool-registry.js` 能力重叠但实现分离。
- **运行方式**：`npm run launch`（直接用已构建的 dist-renderer）/ `npm start`（先 build 再启动）；数据目录 `~/.webagent`，
  兼容 `dsagent` 命令、`window.dsagent`、`X-DSAgent-*` 头。
- 测试：`test/runtime/*.test.js` 共 26 个 node:test 用例，另有 `test/datalog.test.js`、`json-repair.test.js`、`test/e2e/webapp.spec.js`（Playwright）。
