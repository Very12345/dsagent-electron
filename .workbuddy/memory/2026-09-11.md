## 稳定性专项：网页版工具调用卡死（根因定位并修复）

### 复现方式（可复用）
- 试验工作区 `D:/Code/_wa-stability-lab`（24 个合成 .js 文件，可随时删除）
- 驱动脚本 `D:/Code/_wa-driver/drive.js`：建项目→建会话(project 模式)→发 Run→
  订阅 SSE，逐事件打时间戳，输出「关键事件序列 / 事件类型统计 / 是否收到 run.completed」
- 关键：**本机环境变量里配了代理**(http_proxy/http_proxy 指向 127.0.0.1:40627)，
  curl 访问 loopback 必须加 `--noproxy '*'`，否则拿到代理的错误响应
- Runtime 必须用受管后台任务启动（run_in_background），
  用 `nohup ... &` 会被工具调用回收，且会留下残留 runtime.json/runtime.lock

### 根因（主因）
**DSML 单参数包装未解包 → 工具永久失败 → 模型无限重试 → 任务永不结束 → 界面永久转圈**

- `system-prompt.js` 教模型用 `{"tool":"名","params":{...}}`
- `tool-loop.js` 的 4 个解析器都写了 `arguments ?? params`（48/160/237 行，第 18 行还把该格式写成文档）
- 但 **`src/runtime/deepseek-dsml.js` 的解包白名单只有 `arguments`，漏了 `params`**
- DeepSeek 网页版走的正是 DSML，于是
  `<parameter name="params">{"path":"a.js"}</parameter>` → `{params:{path:'a.js'}}`
  → 执行器 `params.path` 为 undefined
- 连锁后果：
  - `read_file` → `resolvePath(undefined)` 解析成**工作区根目录** → `readFileSync(目录)`
    → `EISDIR: illegal operation on a directory, read`（**绝对路径也照样失败**）
  - `exec_command` → command undefined → 执行空命令 → 静默 success + 空输出
- 模型因此改参数名重试（file / filePath / filename / offset+limit…），每轮都产出正文，
  于是「AI 一直在输出、界面一直转圈」

### 另外查到的 4 个独立问题
1. **工具清单从未注入提示词**：旧架构 `lib/tool-docs.js` 在迁移中被删且无替代
   （历史提交 c9b36c6 正是为「避免缺参」而注入工具 schema）。实测模型先猜
   `list_files`、`ls` 全失败，白耗 2 轮。且未声明本机 shell，模型在 Windows 上
   试 `ls -la`/`find` 全报错。
2. **`glob` 对任何带路径的模式返回空**：旧实现把整个 pattern 当文件名后缀比
   （`entry.name.endsWith('src/**/*.js')` 永假）。实测 `src/**/*.js`、`**/*.js` 都返回 []。
3. **`read_file` 忽略 `limit`**：只认 start/end，模型传 limit 时返回整个文件
   （模型自己在思考里点出了这个不一致）。
4. **`rg`/`find_symbols` 依赖外部 ripgrep 二进制**，本机没有 → 全部 `spawn rg ENOENT`
   （这也是 `full-tool-chain` 测试长期失败的原因）。**尚未修复**。

### 次要发现
- 长任务阻塞在审批时（`ask` 风险工具）最长可达 5 分钟，期间无专门状态事件；
  渲染层 `store.ts` 把事件裁到最近 500 条，而审批横幅是从这个窗口算的
  （`pendingApprovals`），长任务里横幅可能被挤出窗口而消失，用户就再也批不了。
- `response.output_text.reset` 是设计行为（每轮工具开始时清掉上一轮中间文本），
  但配合主因 bug 就形成「文字反复闪现又消失、最终答案永不出来」的观感。
- 终态事件由 `run-service` 的 `finally` 保证发出，所以不会真永久卡；
  但 `maxToolRounds=20` 叠加每轮最长 5 分钟审批，理论上可转 100 分钟。

### 关键教训（下次排查直接照做）
1. 先看**工具调用的实际参数串**，别只看错误信息 —— 本次错误信息（EISDIR）极具误导性，
   真凶是上游多包了一层 `params`。
2. 同一份协议有多个解析器时，**逐个对齐**；本次只有 5 个里的 1 个漏了。
3. 「提示词教模型做什么」与「代码实际接受什么」必须一致，
   不一致会产生自我施加的永久失败循环。
