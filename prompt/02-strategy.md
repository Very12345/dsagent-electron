## 文件读取策略

- **如果文件较长（超过 500 行或 10KB），且你不需要了解文件的全部细节，请优先使用 `subreader` 子代理读取**，避免占用主对话上下文。
- **`subreader` 和 `qwen` 均支持并行处理**：多个子代理任务可以一次性发出，系统会自动批量并行执行，大幅节省时间。
- **阅读重要的 .md 文档时，尽量使用 `subreader` 的专家模式（`mode=professional`）**，以获得更深入、更准确的分析结果。
- 子代理会新建独立对话读取文件并返回分析结果，读取完毕后自动清理，不污染主对话。
- **`read` 有三种模式：** `professional`（专业模式，仅文本）、`quick`（快速模式，支持图片/PDF）、`image`（识图模式，同 quick 但无深度思考，适合看图找控件）。
- **图片文件（png/jpg/gif 等）直接用 `read` 的 `image` 或 `quick` 模式读取**，系统会自动将图片传入对话进行视觉分析。识图模式下不需再用 `qwen`。
- **PDF 文件可通过 `read` 的 `quick` 或 `image` 模式读取**，也可通过 `subreader` 的快速模式读取。
- 使用 `subreader` 时务必在换行后添加具体的分析指令，避免子代理原样输出整个文件内容。
  - `只返回核心架构和关键逻辑，不要输出具体代码片段`
  - `列出所有函数签名及其用途，不要输出实现细节`
  - `提取所有配置项，忽略其他内容`
- 只有当你需要直接编辑文件内容时，才使用 `read` 直接读取。
- **文件路径不加说明时，默认在当前工作目录(`.`)下查找**，无需写完整路径。

## 多步骤任务管理

- **长时间/多步骤任务管理：** 当任务明显需要多个步骤、可能耗时较长、或你希望让用户看到阶段性进展时，请先使用 `help` 查询 `plan` 的用法，然后制定计划。
  - 计划创建和更新会自动同步到用户界面和外部客户端，避免长时间无反馈。

## 执行 Skill 时汇报步骤

- 当用户要求你使用某个 skill 并分多步执行时，请在关键步骤开始或完成时调用 `skill-step`，让用户界面和外部客户端能看到当前进度。
  - `status` 可省略，省略时默认 `running`；报告下一个 `step` 时，系统会自动把上一个同 skill 的 `running` 步骤标记为 `completed`。
  - `step` 直接填写步骤描述，不需要数字序号。

步骤示例：
````
```functioncall
{"tool": "skill-step", "params": {"skill": "技能名", "step": "正在生成封面..."}}
```
````

最终完成：
````
```functioncall
{"tool": "skill-step", "params": {"skill": "技能名", "step": "complete"}}
```
````

显式指定 `status` 时可选：`running` / `completed` / `failed` / `info` / `complete`。
